# Сервер аккаунтов Memestone 0.23.0

Сервер PHP 8.1+ / MySQL 8 (также проверен MariaDB 10.11) работает на обычном виртуальном хостинге. Нужны `pdo_mysql`, `fileinfo`, `openssl`, HTTPS и возможность создать закрытую папку рядом с корневой папкой сайта. Фронтенд может оставаться на GitHub Pages. Существующий сайт не требуется переносить: API размещается в `/memestone/api/`.

## Установка на REG.RU

1. Создай отдельную базу MySQL и пользователя с доступом к ней. Для текущего проекта создана база `u3368493_Memestone`. Полное имя пользователя базы может отличаться от имени базы и логина панели.
2. Подготовь закрытый пакет: `python3 scripts/package-account-server.py --admin-email=you@example.com --database-name=your_database`. Он появится в игнорируемой папке `private-deploy/`. Не добавляй этот архив или инструкцию с ключом в Git/публичные загрузки. В инструкции указан случайный одноразовый ключ. Для заранее подготовленного администратора поддерживается `--admin-hash-file=/private/path/hash` (native Argon2id, только хеш).
3. Загрузи ZIP в **папку сайта**, распакуй его и удали ZIP с хостинга. Должна появиться папка `memestone/api`. Инструкцию с ключом оставь у себя. Для Nginx без Apache запрети доступ к `api/lib/`, `api/schema.sql`, `api/setup-key.php` в конфигурации Nginx; обычная связка Apache+PHP читает приложенные `.htaccess`.
4. Открой `https://your-domain/memestone/api/install.php`, введи ключ и данные базы. Укажи URL игры, например `https://stisvladnext3-creator.github.io/hearthstonememe/`. Пароль БД остаётся на хостинге. Установщик создаст таблицы и администратора, сохранит конфигурацию вне `DOCUMENT_ROOT` с правами 0600 и отключит повторный запуск.
5. Укажи публичный адрес API в `public/account-config.json` (или в таком же файле уже собранного сайта). Для проекта: `https://moskompremont.online/memestone/api/index.php`. Этот файл не содержит секретов. Повторная сборка не нужна при изменении только этого адреса. Для отдельной сборки подходит `VITE_ACCOUNT_API_URL`.
6. Проверь `…/api/index.php?action=health`: JSON должен содержать `service: memestone-accounts` и `configured: true`. В игре: **Профиль → Аккаунт**. После входа можно явно перенести гостевой прогресс. Проверка на втором устройстве должна показать те же колоды, карты, статистику и завершённые матчи.

На REG.RU включи сайт и действующий SSL-сертификат. Рекомендуемые PHP-параметры: `post_max_size=32M`, `upload_max_filesize=16M`, `memory_limit=128M` или больше. Установка работает только через HTTPS. PHP-секреты не публикуются в сборке сайта. Доступ к данным определяется серверной сессией, а не переданным клиентом ID пользователя или ролью.

Для переноса **всей игры** на этот хостинг распакуй статическую сборку в `/memestone/`, сохрани папку `api/` и замени в её `account-config.json` адрес на `api/index.php`. У сборки должен быть относительный `base` (`npm run build -- --base ./`). Основной сайт за пределами `/memestone/` останется на месте.

## Что сохраняется

- Личные карты, их иллюстрации и положение кадра; установленные дополнения и закреплённые карты; колоды, выбор колоды и оформление карт.
- Настройки, имя для комнат и выбор тренировочного бота. Оригинальные загруженные изображения хранятся отдельными закрытыми файлами.
- Четыре счётчика действий по каждому матчу, итоги партий и победы. Старые итоговые числа переносятся с идентификатором источника, повторный перенос не суммирует их заново.
- Подробная история **завершённых** матчей, начиная с этого обновления. На сервере сохраняется весь архив; на устройстве — последние 100 загруженных матчей плюс ещё не отправленные. Старые подробные логи до обновления восстановить невозможно. Незавершённый бой и сетевая комната остаются на текущем устройстве.

Гостевые хранилища и каждый аккаунт разделены. Выход возвращает гостевые данные, а не оставляет библиотеку предыдущего игрока. Без связи изменения записываются на устройство и отправляются после восстановления соединения. Синхронизация выполняется после изменений, возвращения во вкладку, восстановления сети и примерно каждые 20 секунд. CAS и трёхстороннее слияние объединяют независимые изменения; при одновременном изменении одной колоды сохраняется копия. Удалённые записи передаются как tombstone. Изображения проверяются по SHA-256.

Пароли хешируются Argon2id; на PHP без Argon2 используется версионированный SHA-256 + bcrypt без усечения длинного пароля. Сессии случайные, срок 30 дней; в базе только хеши токенов. Смена/сброс пароля завершает прежние сессии. Есть ограничения частоты входа/регистрации и одноразовые ссылки. Администратор создаётся только установщиком; регистрация/профиль не позволяют назначить роль. У администратора все карты и признак неограниченных ресурсов, снят лимит создания колод. Валюта и квесты ещё не реализованы; будущие операции с ними должны учитывать роль на сервере. Сам матч остаётся браузерным, статистика не предназначена для защиты рейтинговой экономики от накрутки.

Ключ подписи публикаций каталога остаётся на устройстве автора, как в прежней версии; вход в аккаунт сам по себе не переносит права на старые публикации. Установленные из каталога карты и дополнения синхронизируются.

## Почта и восстановление пароля

По умолчанию регистрация по почте/паролю доступна сразу, без подтверждающего письма. Отправка писем выключена, интерфейс восстановления честно сообщает об этом. Для включения создай почту своего домена, настрой доставку PHP `mail()` на REG.RU и SPF/DKIM по инструкции хостинга. В **закрытой** конфигурации установи:

```php
'mail_mode' => 'mail',
'mail_from' => 'accounts@your-domain',
'require_email_verification' => true, // по желанию, для последующих регистраций
```

Проверь реальную доставку ссылки и корректный `frontend_url`. Не используй пароль игрового администратора как пароль SMTP. Ссылки подтверждения действуют сутки, восстановления — 30 минут, токены хранятся только как хеши и используются один раз. Без почтовой настройки сменить пароль можно из вошедшего аккаунта с текущим паролем.

## Резервная копия и обновление

Резервируй базу MySQL и автоматически созданную закрытую папку `.memestone-<id>` рядом с папкой сайта (в ней конфигурация и `files/`). Не выдавай файлы этой папки через веб-сервер. Не меняй путь API при обновлении без переноса закрытой конфигурации: её имя зависит от пути. Обновляй PHP-файлы, сохраняя конфигурацию, БД и `files/`; `setup-key.php` повторно не загружай. Наличие конфигурации блокирует установщик даже при оставшемся setup-файле. Изменение сайта/источников CORS выполняется в закрытой конфигурации `allowed_origins`, без wildcard.

## Локальная проверка

`KEEP_ACCOUNT_SERVER=1 npm run test:account-server` собирает PHP Apache + MariaDB в изолированных Docker-контейнерах, проверяет установку, авторизацию, защиту роли, изоляцию данных/картинок/истории, ревизии, смену пароля и отзыв сессий. Используются только случайные тестовые пароли. API слушает `127.0.0.1:8081`. Для браузерных проверок подними Vite на 5176 с `VITE_ACCOUNT_API_URL=http://127.0.0.1:8081/api/index.php`, собери тестовый preview на 4174 с тем же адресом и запусти `npm run test:accounts-ui`. `npm run test:accounts` проверяет миграцию и слияние без сервера. Тестовые файлы с паролями хранятся только в `/tmp/memestone-account-test/`.
